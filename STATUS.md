Второй отчёт (`my_reports`, 28.09.2026, диск `N:` + 2 скриншота с замечаниями) разобран, найдены и исправлены две проблемы плюс общая жалоба на прогресс:

1. **«Название папки не отобразилось»** — если корневая папка, которую выбрали в «Обзор…», сама и есть обрабатываемая папка (а не родитель с подпапками), список показывал «.» вместо имени. Причина: `gui/folder_list.py` строил имя через `os.path.relpath(folder, root)`, а путь папки относительно самой себя — как раз «.». Теперь в этом случае берётся `os.path.basename`.
2. **«Если файл 1, то название просто — Рентгенограмма»** — по просьбе пользователя единственный снимок в папке больше не нумеруется: результат — `Рентгенограмма.jpeg`, оригинал в архиве — `Рентгенограмма.tif`, без «1» (решение D17, `domain/naming.py`, `planner.py` передаёт число файлов в папке).
3. **«Общий прогресс отображается некорректно»** — полоса должна расти постепенно, а не рывками. Причина: она считалась по событию `file_completed`, которое фаза B (переименования) шлёт для всех файлов папки одной пачкой в самом конце — папка из 12 файлов на 5 минут вообще не двигала полосу, а потом сразу «прыгала». Переключили счётчик на `file_prepared` (конец фазы A — чтение, конвертация, копирование в архив, где и уходит почти всё время): теперь полоса растёт файл за файлом.

Признак «папка обработана» по-прежнему ищет само слово «рентгенограмма», поэтому папки, обработанные до перехода на новую нумерацию, продолжают опознаваться как готовые — пересчитывать ничего не нужно.

## Как продолжать работу

```bash
# окружение разработки (macOS)
uv venv --python 3.8 .venv
uv pip install --python .venv/bin/python -r requirements-dev.txt
.venv/bin/python -m pytest -q

# ручные проверки
PYTHONPATH=src .venv/bin/python -m tifjpg scan /путь           # ничего не меняет
PYTHONPATH=src .venv/bin/python -m tifjpg process /путь        # обработка
PYTHONPATH=src .venv/bin/python scripts/e2e_tree.py create /tmp/дерево
```

Сборка запускается автоматически на каждый push в `main`; артефакты — в разделе Actions.

## Договорённости, которые легко забыть

- Репозиторий остаётся **приватным**; папка `my_reports/` в git не попадает.
- Имя `tifjpg` — для всего нового: пакет, exe, архивы.
- Нумерация файлов — по имени, натуральная сортировка. Порядок съёмки не восстанавливаем.
- Папка архива создаётся как `ИСХ`, существующая (`Исх`) не переименовывается.
- Папка считается обработанной, если число файлов `*рентгенограмма*.jpg/.jpeg` равно числу TIFF.
- Разделитель в имени файла — **пробел**: `Рентгенограмма N.jpeg`, `ИСХ\Рентгенограмма N.tif` (D16, было подчёркивание). Если файл в папке один — без номера, `Рентгенограмма.jpeg`/`.tif` (D17). Признак «обработано» — по вхождению слова, поэтому папки, уже обработанные старой сборкой (с подчёркиванием или с номером у одного файла), по-прежнему опознаются как готовые.
- libvips **нельзя обновлять** без повторной проверки импортов: новые сборки не работают на Windows 7 (`BUILD.md`).
- Коммиты и push — только по явной просьбе пользователя.
